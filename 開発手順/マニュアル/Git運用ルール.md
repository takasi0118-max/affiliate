# Git運用ルール

## AIアフィリエイトサイト開発フレームワーク Version1.0

## 目的

このドキュメントは、GitとGitHubを利用して安全に開発を進めるための運用ルールを定義します。

------------------------------------------------------------------------

# 基本方針

-   Gitで変更履歴を管理する
-   GitHubをバックアップとして利用する
-   1STEPごとにコミットする
-   動作確認後にPushする
-   問題があれば以前の状態へ戻せるようにする

------------------------------------------------------------------------

# 基本的な開発フロー

1.  新しいSTEPを開始する
2.  Cursorで実装する
3.  動作確認を行う
4.  Gitへコミットする
5.  GitHubへPushする
6.  次のSTEPへ進む

------------------------------------------------------------------------

# コミットルール

コミットは必ずSTEP単位で行います。

例

``` text
STEP01 プロジェクト初期構成
STEP02 Config実装
STEP03 Utility実装
STEP04 Site管理
STEP05 Prompt管理
STEP06 楽天API実装
```

コミットメッセージは内容が分かるように記述してください。

------------------------------------------------------------------------

# Pushルール

以下の場合は必ずGitHubへPushします。

-   STEPが完了したとき
-   大きな修正が完了したとき
-   作業終了時

Push例

``` bash
git push origin main
```

------------------------------------------------------------------------

# ブランチ運用

Version1.0ではシンプルな運用とします。

-   main：安定版
-   feature/\*：大きな新機能（必要に応じて）

通常は `main` ブランチで開発し、機能追加時に `feature`
ブランチを利用します。

------------------------------------------------------------------------

# タグ運用

大きな区切りでタグを付けます。

例

``` text
v1.0
v1.1
v2.0
```

------------------------------------------------------------------------

# よく使うGitコマンド

状態確認

``` bash
git status
```

変更内容確認

``` bash
git diff
```

追加

``` bash
git add .
```

コミット

``` bash
git commit -m "STEP06 楽天API実装"
```

Push

``` bash
git push
```

履歴確認

``` bash
git log --oneline
```

------------------------------------------------------------------------

# ロールバック

問題が発生した場合は、Gitの履歴から以前のコミットへ戻せます。

ロールバック前に必ず現在の変更を確認してください。

------------------------------------------------------------------------

# コミットしてはいけないもの

以下はGitへ含めません。

-   .env
-   APIキー
-   パスワード
-   ログファイル
-   一時ファイル
-   **pycache**
-   .venv

これらは `.gitignore` で管理します。

------------------------------------------------------------------------

# 完了チェック

GitへPushする前に確認します。

-   [ ] エラーがない
-   [ ] 動作確認済み
-   [ ] 不要ファイルが含まれていない
-   [ ] .envをコミットしていない
-   [ ] コミットメッセージが分かりやすい
