# 新規テーマ記事作成手順

新しいテーマで、悩み記事・商品紹介記事・ランキング記事の3本を生成する手順です。
Cursorがなくても、コマンドだけで実行できます。

## いつ使うか

| 方法 | 用途 |
|------|------|
| `main.py` | 新しいテーマで記事を**新規生成**し、下書きとして投稿する |
| `scripts/update_wordpress_posts.py` | 生成後にMarkdownを編集し、**既存投稿を上書き更新**する |

関連ドキュメント: [WordPress記事更新手順.md](WordPress記事更新手順.md)

## 全体の流れ

```text
themes.txt にテーマを登録
    ↓
python main.py を実行
    ↓
Markdownを確認・修正
    ↓
WordPress下書きを確認
    ↓
公開
    ↓
（必要なら update_wordpress_posts.py で個別更新）
```

## 前提

- プロジェクト直下（`affiliate` フォルダ）で実行する
- `.env` に API キーと WordPress 接続情報が設定されている
- `SITE_KEY=disaster`
- `OUTPUT_DIR=sites/disaster/output`

### 必要な .env 項目

```text
GEMINI_API_KEY
GEMINI_MODEL
RAKUTEN_APPLICATION_ID
RAKUTEN_ACCESS_KEY
RAKUTEN_AFFILIATE_ID
WORDPRESS_URL
WORDPRESS_USERNAME
WORDPRESS_APP_PASSWORD
SITE_KEY
OUTPUT_DIR
```

## 1. テーマを登録する

`sites/disaster/themes.txt` に、1行1テーマで追加します。

```text
# One theme per line.
防災リュック
非常食
ポータブル電源
```

`main.py` は **未処理の先頭テーマ** を1回の実行で1件だけ処理します。

## 2. 処理済みテーマの管理（自動）

記事生成と Markdown 保存が成功すると、使用したテーマは自動で `sites/disaster/history.json` に記録されます。

- 次回の `main.py` はそのテーマをスキップする
- `themes.txt` の上から、次の未処理テーマが選ばれる
- 記録はテーマごとに3件（problem / product / ranking）

手動で `history.json` を編集する必要はありません。

### すでに作成済みのテーマがある場合

`history.json` が空のままだと、先頭テーマが毎回選ばれます。
防災リュックは既に手作業で作成済みの場合、次のいずれかを行ってください。

**方法A: history.json に1件追記する（再生成を避けたい場合）**

```json
[
  {
    "theme": "防災リュック",
    "article_type": "problem",
    "title": "防災リュックは何が必要？",
    "slug": "emergency-backpack-how-to-choose",
    "markdown_path": "sites/disaster/output/problem-emergency-backpack-how-to-choose.md",
    "status": "draft",
    "wordpress_post_id": 8,
    "created_at": "2026-07-15T00:00:00+00:00"
  }
]
```

`theme` が記録されていれば、次は「非常食」が処理されます。

**方法B: そのまま main.py を実行する**

防災リュックの3記事が再生成され、完了後に `history.json` へ自動記録されます。

## 3. 記事を生成する

プロジェクト直下で実行します。

```powershell
cd c:\Users\takas\Documents\affiliate
python main.py
```

### main.py が行うこと

1. `themes.txt` から次の未処理テーマを取得
2. 楽天APIで商品を5件取得
3. Geminiで悩み・商品紹介・ランキングの3記事を生成
4. 3記事間の内部リンクを追加
5. Markdownを `sites/disaster/output/` に保存
6. WordPressに下書きとして3件投稿
7. 使用テーマを `history.json` に自動記録

### 実行後に確認する出力

```text
Next theme available: True
Markdown saved: True
WordPress drafts created: True
History saved for theme: 非常食
Problem WordPress post ID: 11
Product WordPress post ID: 12
Ranking WordPress post ID: 13
```

WordPress接続に失敗しても、Markdown保存まで成功していれば `history.json` には記録されます（`status` は `generated`）。

## 4. 生成結果を確認する

### Markdown

`sites/disaster/output/` に3ファイルが作成されます。

```text
problem-{slug}.md
product-{slug}.md
ranking-{slug}.md
```

内容・SEO・商品情報を確認し、必要なら編集します。

### WordPress

管理画面で下書き3件を確認します。

- 見出し・商品カード・FAQの表示
- 内部リンク
- タイトル・slug・抜粋

問題なければ公開します。

## 5. あとから更新する

`main.py` で WordPress 下書きが作成されると、投稿IDは `sites/disaster/history.json` に自動記録されます。
`scripts/update_wordpress_posts.py` はこの履歴を読み込むため、**`POST_TARGETS` への手動追記は不要**です。

```powershell
# 新しく作成された投稿IDだけ更新
python scripts\update_wordpress_posts.py 11

# 登録済み一覧を確認
python scripts\update_wordpress_posts.py --list
```

`wordpress_post_id` が記録されていない記事は、更新コマンドの対象になりません。
更新コマンドの詳細は [WordPress記事更新手順.md](WordPress記事更新手順.md) を参照してください。

## 6. 次のテーマを作成する

1. `themes.txt` に次のテーマがあることを確認
2. `python main.py` を再実行
3. 手順4〜5を繰り返す

`themes.txt` の未処理テーマがなくなると、`Next theme available: False` となり、API通信は行われません。

## history.json に記録される項目

| 項目 | 内容 |
|------|------|
| `theme` | 使用したテーマ名 |
| `article_type` | `problem` / `product` / `ranking` |
| `title` | SEOタイトル |
| `slug` | 記事slug |
| `markdown_path` | 保存したMarkdownのパス |
| `wordpress_post_id` | 下書き作成成功時の投稿ID |
| `status` | 下書きあり `draft` / なし `generated` |
| `created_at` | 記録日時（UTC） |

## よくあるエラー

### `Next theme available: False`

`themes.txt` のテーマがすべて `history.json` に記録済みです。新しいテーマを `themes.txt` に追加してください。

### 毎回同じテーマが処理される

`history.json` にそのテーマが記録されていません。生成が途中で失敗していないか、`Markdown saved: True` になっているかを確認してください。

### Gemini / 楽天 API エラー

`.env` の API キーと `.env.example` の項目名を確認してください。Gemini 503 などは自動リトライされる場合があります。

### WordPress 下書きが作成されない

`.env` の WordPress 設定を確認してください。Markdown と `history.json` への記録は成功している場合があります。

## コマンド早見表

```powershell
# 新規テーマで3記事を生成
python main.py

# 生成後、9番の投稿だけ更新
python scripts\update_wordpress_posts.py 9

# 登録済み投稿一覧
python scripts\update_wordpress_posts.py --list
```
