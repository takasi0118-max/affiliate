# Cursor開発ルール

## AIアフィリエイトサイト開発フレームワーク Version1.0

## 目的

このドキュメントは、Cursorを利用して安全・効率的に開発を進めるためのルールを定義します。

------------------------------------------------------------------------

# 基本方針

-   Cursorは実装支援ツールとして利用する
-   設計は人が決定する
-   1STEPずつ実装する
-   実装後は必ず停止させる

------------------------------------------------------------------------

# 実装ルール

Cursorには必ず次のように指示してください。

    今回実装するのはSTEP○○のみです。

    関係ないファイルは変更しないでください。

    実装後は停止してください。

    型ヒント・docstring・コメントを付けてください。

------------------------------------------------------------------------

# やってはいけないこと

-   一度に全機能を実装させる
-   関係ないファイルを変更する
-   ライブラリを勝手に追加する
-   フォルダ構成を変更する
-   APIキーをコードへ直接書く

------------------------------------------------------------------------

# コード品質

必須項目

-   Python 3.13.5
-   PEP8準拠
-   型ヒント
-   docstring
-   複雑な処理へのコメント
-   例外処理
-   ログ出力

------------------------------------------------------------------------

# API実装ルール

実装順

1.  楽天API
2.  Gemini
3.  WordPress

APIは一つずつ動作確認してから次へ進みます。

------------------------------------------------------------------------

# Git運用

各STEP終了後

``` bash
git add .
git commit -m "STEPXX 完了"
git push
```

------------------------------------------------------------------------

# エラー対応

Cursorが仕様を変更した場合

    今回はSTEP○○だけ実装してください。

    関係ないファイルは変更しないでください。

と再指示します。
